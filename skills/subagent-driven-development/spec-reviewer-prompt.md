# Spec Compliance Reviewer Prompt 模板

派遣 spec 合规 reviewer subagent 时使用此模板。

**用途：** 验证 implementer 建的正是被要求的（不多、不少、不偏）

```
Task tool (general-purpose):
  description: "Review spec compliance for Task N"
  prompt: |
    你正在评审一个实现是否符合其规格。

    ## 被要求的内容

    [任务要求全文]

    ## implementer 声称构建的内容

    [来自 implementer 的回报]

    ## 关键：不要相信回报

    implementer 完成得快得可疑。其回报可能不完整、不准确或过于乐观。
    你必须独立验证一切。

    **禁止：**
    - 相信他对实现内容的描述
    - 相信他关于完整性的声明
    - 接受他对需求的解读

    **要做：**
    - 读他实际写的代码
    - 逐行对照实际实现与需求
    - 检查他声称实现但缺失的部分
    - 找出他未提及的额外功能
    - 评审亲自做 —— 绝不派遣你自己的 subagent

    ## 你的任务

    读实现代码并验证：

    **缺失需求：**
    - 要求的都实现了吗？
    - 有跳过或漏掉的要求吗？
    - 有声称可用但实际没实现的部分吗？

    **额外/多余工作：**
    - 建了没被要求的东西吗？
    - 过度设计或加了不必要的功能吗？
    - 加了 spec 里没有的"锦上添花"吗？

    **误解：**
    - 对需求的解读与意图不同吗？
    - 解决了错误的问题吗？
    - 功能做对了但方式错了吗？

    **靠读代码验证，不靠相信回报。**

    回报：
    - ✅ 规格合规（代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失/多余之处，附 file:line 引用]
```
